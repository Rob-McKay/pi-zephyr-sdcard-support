sd: check read and write ranges for overflow

card_read_blocks() and card_write_blocks() rejected a range with
(start_block + num_blocks) > card->block_count. The sum is uint32_t, so
a range that wraps past 0xffffffff passed the check and was sent to the
card. The range check is now done by a new card_range_valid() helper,
used by read, write and erase.

Add tests/subsys/sd/bounds, which runs the SD stack's block read and
write calls against a fake SD host controller that records the data
transfers reaching it: ranges within the card must reach it, and ranges
starting at or running past the end of the card, including ranges whose
end wraps past block 0xffffffff, must be refused with -EINVAL first. It
needs no hardware and runs on native_sim. tests/subsys/sd/sdmmc only
checks that such requests fail, which a real card does on its own by
rejecting the address, so it cannot tell whether the check worked.

Found on a Raspberry Pi 3A+ (BCM283x SDHost): a read of block
0xffffffff reached the card instead of returning -EINVAL.
